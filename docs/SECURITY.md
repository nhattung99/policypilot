# Security model

Workspace writes require the actual GenVM sender to be the administrator. Submission requires the active operator address and approved action category. Evaluation requires the original operator or the workspace administrator. Only the administrator may review a REVIEW, and an operator cannot review their own request even when also the administrator. A request and its verdict are immutable, policy contents have no update write, and the contract rejects a repeated operator nonce. Each newly authorized request must have its own ID.

Only exact public HTTPS evidence URLs are accepted. The contract does not follow redirects itself and rejects non-200 responses surfaced to the contract. The GET response type has no effective URL field or per-call redirect control. Any automatic redirect behavior, egress restrictions, transfer limits, and timeout handling inside GenVM's web module depend on the network configuration. The contract bounds responses after retrieval, limits prompt excerpts, removes common executable and hidden markup blocks, and checks that returned quotes and policy clauses were present. Unsupported responses and unavailable sources cannot produce automatic approval. An approved site's content can still change, be compromised, or contain instructions that mislead a model. Independent interpretation and evidence checks reduce this risk and do not eliminate it.

Public records are readable across workspaces. Do not submit confidential data, credentials, negotiated contracts, or personal details. The registered address identifies an authorized wallet, and human review is an attestation from a wallet. The browser retains only the last tracked transaction reference and display metadata. No keys, seeds, separate LLM API tokens, or spending permissions are required for application configuration. Wallet onboarding may involve the SDK's official MetaMask Snap.

A future executor needs cryptographic binding to chain and contract, policy version, request ID, agent, action, amount, target vendor, expiry, and finalized authorization. It must enforce one-time consumption and define how human decisions are treated. PolicyPilot v1 performs no external execution.
